같은 주소에 식당과 집이 있어도 배달원이 갈 문은 다를 수 있다. 1층 식당에는 보도에서 바로 들어가고, 위층 세대에는 옆의 공동현관을 거쳐 올라가는 식이다. [이전 개발 일지](/ko/devlog/osm-to-unity/)에서는 OpenStreetMap(OSM)에서 건물 윤곽을 가져오는 과정을 다뤘다. 이번에는 배달의 출발점과 도착점이 되는 **상업 시설과 주거 건물**을 중심으로, 같은 윤곽에서 외관과 출입구를 어떻게 고를지 살펴봤다.

## 주거에서 찾아야 하는 문

게임용 분류는 **대분류 → 중분류 → 소분류**로 내려간다. 대분류는 주거·상업처럼 건물의 용도를 나타낸다. 중분류는 빌라·아파트·근린상가처럼 건물 유형을 구분한다. 소분류는 1층 배치나 동 배치처럼 실제 외관과 배달 경로를 바꾸는 구조다.

단독주택에서는 골목의 대문, 마당을 거치는 현관, 도로에 바로 면한 현관을 구분한다. 맞벽 주택이나 연립형 주택은 외벽이 이어져 보여도 세대별 문이 따로 있을 수 있다. 빌라는 여러 세대가 공동현관과 계단을 공유한다. 필로티 주차형에서는 열린 1층의 기둥과 주차면 사이로 보행로가 이어져야 한다. 닫힌 1층에는 일반 벽체를 쓰고, 도로보다 높은 공동현관에는 외부 계단과 층참을 붙인다. 필로티 여부와 외부 계단 유무는 따로 기록한다.

필로티 외관을 생성할 때는 건물 전체 너비보다 **기둥과 계단실을 뺀 유효 폭**이 중요하다. 차가 도로에서 들어갈 수 있고, 주차된 차 옆으로 공동현관까지 걸어갈 수 있어야 한다. 이 공간이 부족하면 닫힌 1층과 일반 공동현관을 기본 후보로 둔다.

아파트는 동 번호와 공동현관을 먼저 찾는 흐름이다. 판상형은 긴 면을 따라 창과 발코니가 반복된다. 탑상형은 여러 방향에 면이 생겨 코어를 중심으로 동선을 잡는다. 창·발코니·승강기 모듈을 두 유형에 공유하고, 마감과 노후도는 별도로 고른다. 기숙사도 생활실 외피를 공유할 수 있지만, 교내 동은 캠퍼스 보행로에서, 도시 생활관은 거리나 자체 부지에서 진입한다.

## 상업에서 찾아야 하는 문

근린상가는 **주문을 받은 점포에 도달하는 경로**로 나눈다. 독립 단층 점포는 보도에서 매장으로 바로 들어간다. 가로 연속 점포는 같은 벽면에 간판과 문이 반복되므로 주문에 맞는 문을 찾아야 한다. 다층 상가는 1층 점포문과 상층으로 올라가는 공용 현관을 함께 쓴다. 상층에 있는 매장은 계단이나 승강기를 지나 층별 문에서 찾는다.

전통시장은 지붕 덮인 골목을 따라 점포를 찾는 아케이드형과 건물 안 복도로 들어가는 실내 상가동형으로 나눴다. 대형 마트·백화점은 고객문과 상품 하역구를 구분한다. 쇼핑몰에서는 공용 입구 뒤 실내 가로가 점포를 잇는 경우와 야외 광장을 중심으로 각 점포문이 나뉘는 경우를 구분한다. 같은 점포 전면 모듈을 쓰더라도 첫 경유지가 보도, 시장 골목, 몰 로비 중 어디인지 달라진다.

1층 상가와 상층 주거가 섞인 건물은 두 분류가 만나는 사례다. 점포문과 주거 공동현관이 확인되면 각각 별도 출입구로 기록한다. 공용문을 쓰는 건물은 들어간 뒤 목적 층과 점포·세대 문으로 갈라진다. 외관의 문, 실내 연결, 주문 안내가 같은 출입구를 가리키도록 할 계획이다.

## OSM 태그를 어디까지 믿을 수 있을까

`building=apartments`는 공동주택이라는 단서다. 층수와 윤곽을 함께 보면 저층 공동주택과 아파트 규모를 가를 수 있지만, 기둥 아래 주차가 있는지는 따로 확인해야 한다. `building=yes`는 그 자리에 건물이 있다는 표기다. 같은 OSM 객체에 `shop=department_store`가 기록돼 있다면 판매시설로 분류할 수 있다. 반면 건물 안에 별도의 식당 POI가 있으면 식당을 입점 시설로 연결하고, 건물 전체 용도는 확인된 범위까지만 기록한다. `building:use`처럼 현재 용도를 나타내는 태그도 입력에 있다면 함께 사용한다. [OSM 건물 태그](https://wiki.openstreetmap.org/wiki/Key:building) · [OSM 건물 용도 태그](https://wiki.openstreetmap.org/wiki/Key:building:use)

인계와 송도에 이 규칙을 시험한 결과다. 같은 객체의 시설 태그, 일부 시설명, 층수와 윤곽을 사용했다. 한 줄 안의 수치는 각 단계까지 판정한 누적 건물 수다.

- **인계** 4,596개 중 대분류 753개, 중분류 322개, 소분류 외관 후보 139개.
- **송도** 1,546개 중 대분류 1,255개, 중분류 869개, 소분류 외관 후보 305개.

소분류 후보의 대부분은 평면 비율과 층수로 고른 판상형·탑상형 외관이다. 두 추출본에서 필로티나 점포문·주거문의 분리까지 확인한 사례는 없었다. 숫자는 이번에 사용한 지도 추출본과 시범 규칙에 대한 결과다.

## 미분류 건물도 거리를 채운다

용도가 미분류인 건물도 윤곽과 기록된 높이로 외관을 만들 수 있다. 저층에는 벽과 창을 몇 칸 배치하고, 중층은 같은 창 모듈에 층 띠와 코너 패널을 더한다. 고층은 패널을 여러 층 반복하고 기단과 상단 마감으로 구간을 나눈다. 어느 벽에 전면 마감을 줄지는 도로의 이름뿐 아니라 외벽과 도로가 마주 보는 방향, 사이를 가로막는 건물이 있는지도 함께 본다. 실제로 어느 문을 쓰는지는 별도로 기록한다.

먼저 검증할 사례는 1층 상가와 위층 주거가 문을 나눠 쓰는 건물이다. 점포 주문과 세대 주문을 각각의 출입구에 연결하고, 같은 개구부를 기준으로 문과 주변 벽을 만들 계획이다. 플레이에서는 두 주문을 직접 배달해 목적지 안내가 서로 다른 문으로 이어지는지, 문을 쓸 때 벽의 충돌체에 막히지 않는지 확인한다.

<h2 id="building-taxonomy">한국 건물 분류표 전체</h2>

각 행은 대분류, 중분류, 외관·출입 구조를 바꾸는 소분류, 판정에 쓰는 OSM 태그, 공유 모듈을 담는다. `B=값`은 `building=값`의 줄임말이다. 부지 전체에 붙은 학교나 병원 태그는 개별 동의 역할과 구분한다. 표시를 열면 각 표를 볼 수 있다. [OSM 건물 태그 값 목록](https://wiki.openstreetmap.org/wiki/Key:building#Values)

| 주거 | 아파트 | 판상형 / 탑상형. 동의 폭·깊이와 코어 배치로 구분. 신식·구식은 마감 옵션 | `B=apartments` + 동 단위 평면·높이. `apartments` 단독이면 공동주택까지만 | 반복 주거층, 동 현관, 승강기 코어, 발코니 |
| 주거 | 기숙사 | 교내 저층 생활동형 / 도시 독립 생활관형. 캠퍼스 내부 접근인지 도로 직결인지 구분 | `B=dormitory` + 부지 관계 | 생활실 반복 외피, 공용 현관·복도 |
| 상업 | 근린상가 | 독립 단층 점포형 / 가로 연속 점포형 / 다층 상가형. 직접 출입하는 점포 수와 상층 공용 코어로 구분 | `B=retail/commercial/kiosk`. `shop=*`, `amenity=restaurant/cafe` 등은 입점 시설로 연결 | 쇼윈도·간판·점포문, 상층 공용 현관·계단 |
| 상업 | 전통시장 | 아케이드 골목형 / 실내 상가동형. 점포가 외부 골목을 향하는지 내부 복도를 향하는지 구분 | `amenity=marketplace` + 시장 경계·건물·보행로 | 아케이드 지붕, 점포 전면, 시장 게이트·실내 통로 |
| 상업 | 대형 판매시설 | 도심 다층 마트형 / 창고형 매장 / 백화점형. 층별 판매장·주차와 하역 위치로 구분 | `B=supermarket`, `shop=supermarket/department_store` + 규모·층 구성 | 대형 벽체·쇼윈도, 고객 로비, 주차 램프·하역문 |
| 상업 | 쇼핑몰 | 실내 몰형 / 야외 가로형. 점포 사이 이동이 내부 통로인지 외부 광장인지 구분 | `shop=mall` + 동 배치·보행 연결 | 공용 몰 로비·내부 가로 또는 야외 광장·반복 점포 |
| 오피스 | 소형 사옥 | 골목 단독현관형 / 1층 쇼룸 병설형. 거리에서 들어가는 업무 현관과 쇼룸의 관계로 구분 | `B=office` 또는 건물 전체 업무 사용 근거. `office=*` 한 점은 사무실 하나일 수 있음 | 작은 업무 현관·코어, 쇼룸 전면 |
| 오피스 | 일반 오피스 | 벽·창 격자형 / 유리 전면형. 입면 선택이며 로비와 출입 모듈은 공유 | 위와 동일. 외벽 자료가 있으면 반영 | 벽·창 패널 또는 커튼월, 공용 로비·승강기 |

| 근거가 있는 범위 | 저장할 분류 | 생성할 외관·동선 |
|---|---|---|
| **용도와 구조가 확인됨** | 대·중·소분류 확정 | 확인된 외관 구조와 출입구를 적용. 수동 지정은 지정한 필드에 우선 적용 |
| **건물 용도만 확인됨** | 대·중분류 확정, 소분류 미정 | 규모에 맞는 공용 외피와 성립하는 기본 진입을 사용. 생성한 진입은 실제 출입구와 구별해서 기록 |
| **건물 안 입점 시설만 확인됨** | 건물은 기존 분류 또는 미분류, 해당 시설만 등록 | 윤곽·주소·층이 맞는 범위에 시설을 연결. 확인된 층이나 출입구가 있으면 그 시설 경로에만 적용 |
| **`building=yes`·빈 값·알 수 없는 값, 또는 건물 전체 용도 근거가 충돌함** | 확인 가능한 가장 구체적인 분류까지만 저장. 용도 근거가 없으면 미분류 | 윤곽·높이·도로 방향으로 기본 외관 생성. 인근 토지 이용이나 직사각형 평면은 외관의 보조 단서로 사용 |

<details class="taxonomy-details">
<summary>공유 외관·출입 모듈</summary>

<div class="taxonomy-table" role="region" aria-label="공유 외관·출입 모듈" tabindex="0">

| 공유 모듈 | 같은 구조를 쓰는 유형 | 출입구 연결 |
|---|---|---|
| **거리 직결문 + 반복 전면** | 근린 점포, 지상 의원, 작은 민원시설, 독립 예배시설 | 전면의 문을 시설과 직접 연결 |
| **공용 현관 + 수직 코어 + 층별 문** | 빌라, 다층 상가, 상층 의원·교회, 오피스, 호텔 | 거리 입구 ID와 실내 목적층·시설 문을 연결 |
| **마당·단지 정문 + 동별 현관** | 아파트 단지, 학교, 병원, 사찰, 리조트, 공장 | 정문을 경유점으로 두고 배달 목적 동의 문을 따로 지정 |
| **관객·여객 로비 + 검표·통제문** | 공연장, 경기장, 역, 공항·항만 | 공개 구역의 인수처와 통제문을 별도 지점으로 기록 |
| **차량 진입 + 셔터·도크·하역구** | 작업장, 물류센터, 대형 매장, 전시장, 소방시설 | 차량문과 보행문을 분리하고, 차량문에는 하역·출동 등 실제 역할을 부여 |
| **저층부 + 상부 반복 외피** | 아파트, 오피스 타워, 숙박, 복합건물 | 상부 외피나 마감이 바뀌어도 저층 현관의 역할과 ID를 유지 |

소형 부속 건물은 공용 배경 모듈을 쓴다. `stilt_house`, `houseboat`, `tent`, `bunker`처럼 드문 형태는 개별 에셋 후보로 둔다. `construction`, `ruins`, `abandoned:building=*`는 상태로 기록하고 자동 배달 대상에서 제외한다. `building=no`나 철거된 객체는 독립 건물을 생성하지 않으며, `building:part=*`는 상위 건물의 일부로 처리한다.
